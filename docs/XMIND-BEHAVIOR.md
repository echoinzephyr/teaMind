# Xmind 处理逻辑与主题规则：第一轮分析

分析对象为本机 Xmind `26.5.1107.202609082009`，归档内版本为
`26.05.01107`。以下规则来自客户端随附脚本的静态分析；需要实际操作和
文件样本确认的部分单独注明。这里记录行为、数据关系和代码定位，不收录
客户端源码、预设主题内容、字体、图片或其他资源。

## 1. 状态与处理流程

编辑过程至少区分：文档/画布、选中对象、指针目标、文字或拖拽编辑会话、
视口位置与缩放。它们不是同一类状态。

- 新增、主题切换等结构操作会先调用结束当前编辑会话的公共入口。
  如果能完成文字提交则先提交，否则清理编辑会话和指针目标。
- 文字输入、输入法组合、选择文字、结束输入分别处理。文字编辑期间的
  图形反馈使用草稿内容生成，而不是让一次布局过程直接改写模型。
- 平移、缩放使用视口手势的开始/变化/结束请求。撤销文档与改变视口有
  不同入口，不能把每次平移都当作一次文档命令。
- 处理器会按选中对象类型、允许的结构、锁定状态判断命令是否可用；
  不可执行时返回空处理器，由界面禁用相应操作。

对应 teaMind：保留原生 TextBox 的输入法处理；统一提交/取消草稿入口；
绘制、视口、选择状态和可撤销的文档修改分别更新。

## 2. 新增、移动、复制与删除

### 新增

- 子主题添加到选中节点下，并展开父分支；处理器能作用于多个有效选中项。
- 普通同级主题可在当前主题之前或之后插入。对中心主题执行“之后插入”
  时转为新增子主题；“之前插入”对根节点有限制。
- 添加后更新选择，再根据编辑设置决定是否进入文字编辑。
- 默认名称区分主分支和子主题，并根据父节点已有孩子数量生成序号。
- 节点编号规则等语义属性会按情境继承，不能简单复制上一节点的所有字段。
- 不平衡导图维护首半侧分支数量；新增、移走或删除分支时另行维护这个值。
- 新画布辅助函数沿用当前画布的配色和样式主题，初始化中心及四个主分支。
  这不等于所有模板或新建文件入口都固定生成四个分支。

### 移动

- 同父节点排序先扣除待移动节点在目标位置之前占据的数量，避免索引偏移。
- 移入折叠分支会展开目标，并将插入位置调整到相应孩子列表末尾。
- 普通树节点移动、转为自由主题、自由位置调整是不同路径。
- 移动同时维护原侧/目标侧信息；自由定位时记录相对于作用范围的偏移。
- 复制路径先克隆并分配新 ID，再按普通节点或自由主题放置；有关联关系
  时复制相应克隆关系。
- 结构层使用可移动对象接口检查是否能移动。禁止移入自身后代的具体
  底层检查仍需继续追踪；不能仅凭这个接口就宣称已还原所有保护规则。

### 删除

- 普通删除按主题、图片、关系线、边界、区域等选中类型分派；正在编辑
  文字时不会把正文 Delete 直接当作删除整支主题。
- 删除普通主题后，选择优先回到存活的前一同级，再尝试后一同级，最后
  回到父节点。自由主题的选择回退另行处理，还会考虑视口可见性。
- “仅删除节点”是独立命令：把孩子提升到原父节点，再移除该节点，并
  调整相关边界与概要范围。
- 多选、跨范围边界和关系线清理的完整结果，仍需用真实保存文件验证。

## 3. 平衡布局与拖拽

- 平衡模式读取实际分支高度与间距，从两端累计空间确定两侧分界。
  边界和概要覆盖的分支作为分组约束参与计算，避免任意拆开。
- 顺时针结构的第一半侧向右、向下排列，第二半侧向左、向上排列。
  不应把数组顺序、屏幕从上到下的顺序、左右方向视为同一个概念。
- 布局因子会读取旧方向/位置，并在计算后与新偏移协调；平衡模式可能
  调整分界，不能假定它永远保持每个主分支原来的方向。
- 每种结构提供拖放目标、插入索引、插入标记、允许覆盖的范围及方向键
  导航规则。拖拽交互应该展示目标位置，然后提交结构变化。

teaMind 当前采用“新主分支放到较轻侧、已有方向保留、用户可主动均衡”的
策略。这是目前的产品选择，并不是宣称完全复现 Xmind 的平衡算法。

## 4. 撤销、保存与异步归属

- 文档历史包含当前值、前一条和后一条。建立历史节点与替换当前节点值
  是不同操作。
- 已找到一个约 5 ms 的连续文档变更捕获窗口：窗口内后续变化替换当前
  历史节点，窗口外再建历史节点。这是该处理通路的实现参数，不是所有
  用户操作都必须按 5 ms 合并的产品规则。
- 标记保存时记录当前文档内容；脏状态比较当前内容和保存基准。
- 异步打开文件使用加载序号，丢弃过期结果；写回文档还检查文件归属，
  防止较早的异步结果覆盖后来打开的文件。

teaMind 保留独立命令的撤销记录，仅合并显示刷新。AI、保存快照和文件
打开结果都应绑定原文档身份；不要照搬历史捕获计时常数。

## 5. 主题：配色与样式分别管理

已确认存在独立的 `colorThemeId` 与 `skeletonThemeId`。

- 配色层管理画布、文字、填充、边框/连线颜色及多分支色列。
- 样式层管理节点形状、连线形状、箭头、字体、字号、字重、文字对齐、
  填充模式、线宽、线型，并可以携带结构配置与扩展样式。
- 类别至少包括画布、中心、主分支、子主题、自由主题、概要主题、标注
  主题、重点/次要/过期主题、边界、概要线、关系线和区域。
- 本机该包中静态配色表含 553 条记录，样式表含 60 条记录；其中包含
  隐藏/变体等数据，不等于界面显示相同数量的可选主题。
- 智能配色还有生成流程：根据基础色列生成普通和多分支方案，去重并生成
  标识；文字颜色通过背景对比度选择候选色或黑白回退色。

teaMind 当前的四组色板还没有覆盖这套角色、继承和样式组合能力。

## 6. 最终样式的解析顺序

通用解析器对每一项属性分别选择第一个非空值，保留每层来源：

1. 扩展在节点设置前提供的值。
2. 节点显式设置。
3. 画布 `global` 类设置。
4. 节点所带的用户样式类，按其声明顺序。
5. 扩展在默认类前提供的值，例如某些自动分支颜色。
6. 默认类：深度层级类优先，再到节点角色类。
7. 扩展提供的基础回退值。
8. 硬编码基础默认值。

扩展还能重写某一层或最终值，因此不能把这个顺序直接等同于固定的 CSS
继承。已确认字体和线宽等属性存在调整全局值适用条件的处理。

必须区分这些状态：

- 未设置：继续向低优先级查找。
- `inherited`：对支持继承的属性，解析父节点最终值。
- `none`：明确无填充或无线型等含义，不等于“未设置”。
- 明确的颜色、线宽或字重：真正的覆盖值，包含透明度时需保留透明度。

边框某些继承值跟随本节点连线结果；主分支自动连线色按主分支索引轮换，
子级连线可以继续继承。自由主题自动色与关系线跟随目标对象的颜色又是
独立机制。不能仅用“父节点颜色传给所有孩子”概括整套规则。

## 7. 切换主题时的处理

- 切换配色先更新主题样式，清理颜色相关的层级/扩展设置，并重置受影响
  对象的显式颜色与部分富文本颜色，让新配色能实际生效。
- 切换样式处理形状、字体和线型等属性，清理对应旧覆盖；有结构主题时
  更新相关结构设置，并可能清理自定义宽度。
- 整体应用自定义主题还有独立路径，会清理主题 ID 和结构扩展后重新应用。
- 这些命令先结束当前文字编辑；切换同一主题 ID 时可以直接返回。

因此“切换任何主题都保留全部单节点覆盖”并不是这里观察到的通用行为。
teaMind 应提供明确的“保留自定义”与“重置相关样式”语义，切换作为一次
可撤销操作。不能把 `false`、未设置和继承混为一谈，特别是加粗/斜体。
